# STEP 5 — 화면 실행 및 수동 확인

HTML·CSS·Vanilla JS로 8개 화면을 작성했습니다. 설치, 빌드, SQL 실행, 서버 실행, 브라우저 조작, 스크린샷 및 테스트를 작성자가 수행하지 않았습니다. 아래는 사용자가 직접 확인하는 절차입니다.

## 1. 준비와 CMD 실행

STEP 1~4의 DB와 API가 준비되어 있어야 합니다. 이번 단계는 추가 SQL, 패키지 설치, Node.js 및 빌드 작업이 없습니다. 기존 .env를 유지하세요.

실행 중인 서버가 있으면 Ctrl+C로 종료하고 다음을 실행합니다.

```cmd
cd /d C:\AIO4\Day12_demo\project
.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

브라우저에서 `http://127.0.0.1:8000`을 엽니다. `/products`로 이동해야 합니다. HTML 파일을 탐색기에서 직접 열지 않습니다. APP_ORIGIN의 기본값과 같은 주소를 사용하며, localhost로 바꾸지 않습니다.

화면 파일은 FastAPI가 FileResponse로 반환하고 `/static`에서 CSS/JS를 제공합니다. Jinja2나 외부 CDN, 프레임워크, npm이 필요하지 않습니다. SQL을 최초 적용하는 새 DB에서는 schema.sql → seed.sql → step3_functions.sql → step4_functions.sql 순서를 따릅니다.

## 2. 화면 주소

| 화면 | 주소 | 기능 |
|---|---|---|
| 상품목록 | /products | 목록, 페이지 이동, 품절 표시 |
| 상품상세 | /products/{상품 UUID} | 설명·가격·재고·수량, 장바구니 담기, 바로 결제 |
| 로그인 | /login | 이메일·비밀번호 로그인 |
| 회원가입 | /signup | 이메일·비밀번호·이름·연락처·주소 입력 |
| 장바구니 | /cart | 조회·수량 변경·삭제·주문 생성 |
| 결제 | /payment?order_id={주문 UUID} | 주문·배송지 확인, 모의 결제·재시도 |
| 회원정보 | /account | 정보 수정·비밀번호 변경·탈퇴, 구매내역 링크 |
| 구매내역 | /purchases | 완료 주문 목록·페이지 이동·상세 펼치기 |

회원가입에는 비밀번호 확인을 추가했으며 확인값은 서버로 전송하지 않습니다. 상품 이미지는 DB 컬럼이 없어 CSS 일러스트로 표시합니다. 업로드 기능은 추가하지 않았습니다.

## 3. 기능 확인 순서

각 항목에 O/X로 답해주세요.

### 상품·가입·로그인

- [ ] 비로그인 상태에서 상품목록과 상세가 표시된다.
- [ ] 품절 상품은 품절 배지와 비활성 구매 버튼이 표시된다.
- [ ] 상품목록의 마지막 페이지에서는 다음 버튼이 비활성화된다. 현재 샘플 5개만 있으면 페이지 버튼은 숨겨진다.
- [ ] 회원가입에서 필수 값과 비밀번호 확인을 검사한다.
- [ ] 가입 성공 후 로그인 화면에 완료 안내가 표시된다.
- [ ] 잘못된 비밀번호·중복 이메일은 서버 오류 메시지로 안내된다.
- [ ] 로그인 성공 후 상품목록으로 이동하며 로그아웃 버튼이 표시된다.
- [ ] 로그아웃 후 상품목록으로 이동한다.

### 장바구니·주문

- [ ] 상품상세에서 수량을 입력하고 담으면 완료 안내와 장바구니 이동 링크가 표시된다.
- [ ] 수량은 현재 재고 이내의 양의 정수만 허용한다.
- [ ] 장바구니에서 수량 변경·삭제 후 합계가 갱신된다.
- [ ] 상품을 모두 삭제하면 빈 장바구니 안내가 표시된다.
- [ ] 가격·재고 새로고침으로 현재 상태를 다시 확인할 수 있다.
- [ ] 재고가 부족한 항목이 있으면 주문 버튼이 비활성화된다.
- [ ] 주문하고 결제하기를 누르면 주문을 생성하고 결제 화면으로 이동한다.
- [ ] 상품상세의 바로 결제는 기존 장바구니를 유지하고 별도 주문의 결제 화면으로 이동한다.

### 모의 결제

- [ ] 결제 화면에 주문 상품·수량·단가·합계·배송지가 표시된다.
- [ ] 실패를 선택하고 결제하면 실패 사유가 표시되고 주문은 pending이다.
- [ ] 성공을 선택하여 재시도하면 상품목록으로 이동하고 완료 안내가 표시된다.
- [ ] 구매내역에서 결제 완료 주문을 확인할 수 있다.
- [ ] 이미 결제된 주문의 결제 화면을 다시 열면 완료 상태와 구매내역 링크가 표시된다.
- [ ] 재고 부족 상태에서는 일반 결제 버튼이 비활성화된다.
- [ ] 요청 처리 중에는 해당 영역의 버튼·입력이 비활성화되어 연속 제출을 막는다.

결제 요청 전에 UUID와 금액·모의 옵션만 sessionStorage에 저장합니다. 비밀번호/JWT/주소는 저장하지 않습니다. 네트워크 오류 등으로 결과를 못 받은 경우 새 키를 만들지 않고 이전 결제 결과 확인 버튼으로 동일 요청을 보냅니다. 이때 결과 옵션을 바꿀 수 없습니다. 서버에서 명확한 실패 결과를 받으면 다음 시도에는 새 키를 사용합니다. 사이트 저장소를 사용할 수 없으면 요청을 보존하지 못했다는 안내와 함께 결제를 시작하지 않습니다.

브라우저의 뒤로 가기나 새로고침으로 결제 화면을 다시 열더라도 실제 재고 차감과 성공 결제 중복은 서버 트랜잭션에서 제한합니다. 바로 주문 자체를 여러 번 생성하면 별도 pending 주문이 생길 수 있습니다.

### 회원정보·구매내역

- [ ] 회원정보가 조회되고 수정한 이름·연락처·주소가 저장된다.
- [ ] 기존 주문 상세의 배송지는 회원정보 수정 후에도 유지된다.
- [ ] 비밀번호 변경 시 현재 비밀번호·새 비밀번호 확인을 검사한다.
- [ ] 변경 성공 후 로그인 화면으로 이동하고 새 비밀번호로 로그인된다.
- [ ] 구매내역에 paid 주문만 표시되며 상세 펼치기에서 상품·금액·배송지를 확인한다.
- [ ] 구매가 없으면 빈 목록 안내가 표시된다.
- [ ] 탈퇴 안내 확인과 현재 비밀번호 입력 후 탈퇴가 가능하다.
- [ ] 탈퇴 후 로그인은 거절되고 DB의 주문·결제 기록은 유지된다.

탈퇴 시나리오는 다른 항목을 확인한 뒤 마지막에 진행하세요.

## 4. 반응형 확인 — F12

브라우저 개발자도구(F12)에서 기기 도구 모음(Ctrl+Shift+M)을 열고 반응형 모드의 너비를 순서대로 변경합니다. 확대/축소는 100%로 맞추세요.

| 너비 | 확인할 레이아웃 | O/X |
|---|---|---|
| 360px | 상품 카드 2열, 하단 메뉴, 본문 가로 스크롤 없음 | |
| 360px | 로그인/가입 입력과 버튼이 화면 안에 들어옴 | |
| 360px | 상세·장바구니·결제는 세로 배치, 합계·버튼 가림 없음 | |
| 360px | 회원정보·구매내역의 긴 주소·주문번호 줄바꿈 | |
| 360px | 하단 메뉴가 마지막 버튼이나 메시지를 가리지 않음 | |
| 768px | 상품 카드 3열, 상단 메뉴, 하단 메뉴 숨김 | |
| 768px | 상품상세의 일러스트와 설명이 2열로 표시됨 | |
| 1200px 이상 | 상품 카드 4열, 본문 최대 너비 유지 | |
| 1200px 이상 | 장바구니·결제는 본문/금액 요약 2열 | |
| 1200px 이상 | 회원정보는 계정 안내/편집 영역 2열 | |

공통 확인 항목:

- [ ] 버튼·입력 영역의 높이가 약 44~48px 이상으로 터치하기 편하다.
- [ ] Tab 키로 이동할 때 포커스 테두리가 보인다.
- [ ] 각 입력에 연결된 레이블이 있고 로딩·오류·완료 안내가 보인다.
- [ ] 긴 상품명·주소·오류 메시지가 화면 밖으로 넘치지 않는다.
- [ ] CSS/JS 로딩 실패나 작업 오류가 있으면 개발자도구 Console/Network의 오류를 확인할 수 있다.

## 5. STEP 6과의 경계

현재 비로그인 상태에서 인증이 필요한 API를 호출하면 로그인 필요 메시지와 로그인 링크를 표시합니다. 자동 화면 이동 및 내부 next 경로 검증·로그인 후 직전 화면 복귀는 아직 연결하지 않았으며 STEP 6에서 진행합니다.

로그인 성공은 현재 상품목록으로 이동합니다. 비밀번호 변경·탈퇴 완료 후 로그인 화면으로 이동하는 것은 해당 작업의 완료 처리입니다. 보호 화면 자동 이동 기능과 구분됩니다.

## 6. 가정과 피드백

가정: 상점 표시는 AI-Marine Shop이며 초록·파랑 테마, 시스템 글꼴과 CSS 일러스트를 사용합니다.

가정: 상품목록은 페이지당 12개, 구매내역은 10개를 표시합니다.

가정: 구매내역 상세는 별도 화면 대신 목록 안에서 펼쳐 확인합니다.

가정: 결제 성공 후 상품목록으로 이동하여 완료 안내를 표시합니다.

가정: 최신 Chrome/Edge 등 ES 모듈과 기본 브라우저 API를 지원하는 환경을 사용합니다.
